# Verify a Release

Don't trust us, verify us. Every Community Edition release from the first CI-built tag onward (releases up to 2.4.6 predate signing) is built and signed in GitHub Actions from a `vX.Y.Z-ce` tag. No release image is pushed from a laptop.

| Artifact | Where | Evidence |
| :--- | :--- | :--- |
| First-party images | `ghcr.io/devopssquaddev/zelkor-*:X.Y.Z` | keyless cosign signature, SLSA v1 provenance, SPDX SBOM |
| Helm charts | `oci://ghcr.io/devopssquaddev/charts/zelkor-platform` and `zelkor-agent` | signature, provenance |
| Upstream images (Langfuse, datastores) | their own registries, never mirrored | digests in the release manifest attested on the platform chart |
| Fail-closed matrix, gate results, SBOMs | GitHub release assets | generated by the release run |

Every signature is bound to one identity. Anything signed elsewhere fails.

| Field | Value |
| :--- | :--- |
| OIDC issuer | `https://token.actions.githubusercontent.com` |
| Certificate identity (regexp) | `^https://github\.com/devopssquaddev/zelkor-platform/\.github/workflows/release\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+-ce$` |

## Verify an image or chart with cosign

Install [cosign](https://docs.sigstore.dev/cosign/system_config/installation/), then:

```bash
ISSUER=https://token.actions.githubusercontent.com
IDENTITY='^https://github\.com/devopssquaddev/zelkor-platform/\.github/workflows/release\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+-ce$'
VERSION=X.Y.Z   # the release you run, e.g. from: helm list -n zelkor
IMAGE=ghcr.io/devopssquaddev/zelkor-mcp:$VERSION

cosign verify --certificate-oidc-issuer "$ISSUER" --certificate-identity-regexp "$IDENTITY" "$IMAGE"
cosign verify-attestation --type slsaprovenance1 \
  --certificate-oidc-issuer "$ISSUER" --certificate-identity-regexp "$IDENTITY" "$IMAGE"
cosign verify-attestation --type spdxjson \
  --certificate-oidc-issuer "$ISSUER" --certificate-identity-regexp "$IDENTITY" "$IMAGE" \
  | jq -r .payload | base64 -d | jq .predicate > sbom.spdx.json
```

The provenance names the repository, the source tag, the commit and `.github/workflows/release.yml`. A tag whose version does not match `Chart.yaml` and every first-party image tag fails the release before anything is built.

For the chart, use the digest `helm push` printed in the release run, or resolve it with `crane digest ghcr.io/devopssquaddev/charts/zelkor-platform:$VERSION`, and verify `ghcr.io/devopssquaddev/charts/zelkor-platform@<digest>` the same way. The release manifest (first-party, chart and upstream digests) is attested on it:

```bash
cosign verify-attestation --type https://zelkor.io/attestations/release/v1 \
  --certificate-oidc-issuer "$ISSUER" --certificate-identity-regexp "$IDENTITY" \
  ghcr.io/devopssquaddev/charts/zelkor-platform@<digest> | jq -r .payload | base64 -d | jq .predicate.upstream
```

GitHub's own attestation works too: `gh attestation verify oci://$IMAGE --repo devopssquaddev/zelkor-platform`.

## Verify what runs in your cluster

```bash
zelkor verify zelkor-platform --env staging
```

[`zelkor verify`](../cli.md#verify-a-release) checks the digest every running Zelkor container pulled, with the identity above, and exits non-zero on any failure.

## Admit only signed images

With [Kyverno](https://kyverno.io/) 1.12 or later in the cluster, enable the chart policy:

```bash
helm upgrade zelkor-platform oci://ghcr.io/devopssquaddev/charts/zelkor-platform --version "$VERSION" \
  -n zelkor --reuse-values --set security.imageVerification.enabled=true
```

The `ClusterPolicy` rejects any Pod whose `ghcr.io/devopssquaddev/zelkor-*` image lacks the release signature or provenance, and pins admitted images to their digest. Start with `--set security.imageVerification.failureAction=Audit` to report without blocking. Scope it with `security.imageVerification.namespaces`. Locally built `:dev` images are rejected while it enforces.

## Release gates

Each release publishes:

- `fail-closed-matrix.md`: the security test run grouped by promise (auth, guardrails, egress, DNS egress, admin plane, provider keys, component down). A promise with no passing test shows as GAP, never as pass.
- `upgrade-rollback.json`: upgrade from the previous release and `helm rollback`, with zero failed requests through the gateway.
- `retry-storm.json`: 30 minutes of 100% provider failures; Envoy memory stays flat and under the ceiling in [`scripts/release/gate-thresholds.json`](../../scripts/release/gate-thresholds.json).

Report vulnerabilities as described in [SECURITY.md](../../SECURITY.md). Fixed CVEs are in the [CVE log](cve-log.md).
